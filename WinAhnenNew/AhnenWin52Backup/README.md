`backup` reads the five mapped Paradox tables, including encrypted record blocks and memo text, and writes a complete `.hej` file. It creates the output through a temporary file, validates it, refuses to overwrite an existing target, and never writes to the source database. `inspect` validates an existing HEJ file; `inspect-db` reports a Paradox 5/7 table schema and record count without displaying record contents:

```powershell
dotnet run --project AhnWin52Backup.Cli --framework net10.0 -- backup C:\path\to\database C:\path\to\backup.hej
dotnet run --project AhnWin52Backup.Cli --framework net10.0 -- inspect C:\path\to\backup.hej
dotnet run --project AhnWin52Backup.Cli --framework net10.0 -- inspect-db C:\path\to\AWD.DB
dotnet run --project AhnWin52Backup.Cli --framework net10.0 -- inventory-db C:\path\to\database
dotnet run --project AhnWin52Backup.Cli --framework net10.0 -- create-template C:\path\to\new-database
dotnet run --project AhnWin52Backup.Cli --framework net10.0 -- create-generated-template C:\path\to\new-generated-database
dotnet run --project AhnWin52Backup.Cli --framework net10.0 -- --set-passwd
```

`--set-passwd` prompts for the Paradox password twice without echoing it, then stores it as a Windows Generic Credential for the current Windows user. Do not pass the password as a command-line argument. The credential is machine-persistent but remains protected by the Windows user profile. The current restore uses the encryption metadata carried by the verified embedded table templates; it does not retrieve this credential.

`inventory-db <db-dir>` inventories all top-level Paradox `.DB` schemas and reports the presence of their `.PX`, `.MB`, `.XG<n>` and `.YG<n>` companions using headers only; it does not read records or memo bytes. Counts are declared header counts, not a verified traversal. It refuses missing primary indexes, unpaired XG/YG files and orphan sidecars. Table and field names are still metadata and may be sensitive.

`create-template <new-db-dir>` creates a new directory from the embedded, versioned JSON structure manifest and its separately embedded files. It refuses to overwrite any existing file or directory, verifies each embedded SHA-256, then validates the exact file list, Paradox schemas, index pairs and the 168-row `chnt.DB` baseline before publishing the directory. The template contains 18 table families and 113 allow-listed assets: Paradox tables and sidecars, `par.cfg`, `chnt.xml`, stylesheets, and the `FOKO.DBF`/`.MDX`/`.ABK` family. Executables and DLLs are excluded. This command creates structure only; it does not populate the five HEJ tables.

It generates an empty `AWD.DB` and the 168-row `chnt.DB` namesday baseline. Paradox data blocks, index files, and memo sidecars use the encryption metadata declared by the structure manifest. The reader accepts the legacy individual-record variant with one omitted trailing field by padding it. Marriage records use the verified 22-field schema. Literal tabs are preserved. Other unsupported legacy control bytes are discarded and reported as compatibility warnings; restore refuses such input unless `--force` is explicitly supplied. CR/LF line endings inside fields become the HEJ `0x10` marker.

HEJ-to-Paradox restore is available in three guarded modes. The default `restore <file.hej> <empty-template-dir>` accepts only a verified empty template; `restore --fromscratch <file.hej> <new-db-dir>` generates the Paradox families from the manifest and obtains support assets from the verified embedded archive; and `restore --override <file.hej> <existing-db-dir>` replaces the five HEJ-backed table families plus the derived `NM` surname and `occ` occupation-list families in a compatible database directory. `NM` is rebuilt from distinct `AWD.Name` values; `occ` is rebuilt from case-insensitive distinct, non-empty `AWD.Beruf` values. `over.*` remains an empty template family. All modes build in sibling staging directories, verify schemas, row counts, indexes and an HEJ re-export before publishing. `create-template` remains the resource-materialized compatibility fallback. `--force` is required to accept the HEJ reader's reported control-byte losses. The HEJ format omits `Bild` (restored empty) and the auto-increment fields `MRG.Numr`/`sour2.N` (regenerated, not preserved identifiers).

Example:

```powershell
dotnet run --project AhnWin52Backup.Cli --framework net10.0 -- restore --fromscratch C:\path\to\backup.hej C:\path\to\new-database
```

## HEJ wire format confirmed so far

- Text is encoded as Windows-1252.
- Lines and records end with CRLF.
- Fields are separated by byte `0x0F`.
- Embedded line breaks use byte `0x10`.
- Record sections occur in order: individuals, `mrg`, `adop`, `ortv`, `quellv`.
- Individual rows in legacy files may omit one trailing field; the reader pads it as empty.
- Marriage rows contain 22 fields.
